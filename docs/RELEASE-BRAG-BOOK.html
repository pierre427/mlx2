Chapter 2 · How it works

Six mechanisms, drawn

The changes that moved the numbers, plus two research routes, each with the mechanism, the evidence and its limits.

Mechanism 1 · speculation

Qwen3.8-27B decodes with a DFlash2 token tree by default

selected by default for the pinned pairobserved-usedcandidate, not qualified

Since 187c6aa23 the Mac startup default for the pinned Qwen3.8-27B target and DFlash2 drafter is an external draft tree, verified by a TensorFold executor that mlx2 vendors and owns (cfa2ff599). One service changes geometry with the number of active lanes, so every verify forward stays near sixteen target rows.

  • B1 short chat: DFlash2 66–158 tok/s across the two prompts against ordinary 32.7–33.0; the spread is the drafter's acceptance on different text. Tool-call TTFT 0.58–0.59 s against 1.43–1.51 s; JSON 59–60 against 31 tok/s.
  • The tree gains nothing on decode after an 8K prompt: DFlash2 26–36 tok/s against ordinary 31, while native MTP holds 41–51.
  • The week corrected the TensorFold numerical law and replaced it with an mlx2-owned tree GDN; a reversed BAAB run kept 420 outputs identical. qualification/runs/sweep-20261006/lanes/history.md §1B
  • Still a candidate: the semantic gate fails (code fences, creative length) and the native-MTP handoff gate at width 8 missed by 9.8%. qualification/runs/sweep-20261006/lanes/history.md §1D
Mechanism 2 · scheduling · fixed this sweep

Prompts that arrive together decode together

behaviour changeSS-1measured on GPU

Self-MTP decodes a cohort of lanes in one verify forward, and the cohort's width is fixed when it starts. When four chat prompts arrived together and each needed more than one prefill chunk, the first to finish started MTP alone and the other three were left to decode plainly beside it.

  • Qwen3.8-27B native MTP at B4: 46–51 → 104–111 tok/s, now 1.5× ordinary (70–75). q38-routes; final-q38-routes
  • Flash-Next B8: median TTFT 6.8–7.0 → 3.0–3.6 s at the same batch wall time. fn; final-fn
  • The first finisher's TTFT now includes its siblings' bounded prefill; counter mtp_coarrival_holds shows when that happened.
Mechanism 3 · scheduling · new default

A completion-time cost model bounds every prefill stall

new default this sweepsame-code GPU A/Brequalification advised

Decode fairness lets long prompts prefill in slices beside live decode. The old bound kept a running maximum of per-row speed: one fast sample pinned it after a slowdown, a four-row forward cost four times the target, and self-MTP preparation never reported its time. The new estimator predicts each forward's completion time.

  • The external-draft and prompt-lookup routes ran their own prefill loops with fairness off; they now apply the same bound (673aa9fe0), which is what brought DFlash2 and PLD under target in chapter 1.
  • The estimator is recorded in route identity (acadd8b76), so receipts say which rule sized the slices.
Mechanism 4 · speculation on hybrids

Prompt lookup batches on recurrent hybrids and reuses warm prefixes

opt-in routesweep fixB4 at parity

Prompt lookup drafts by copying text the conversation already contains, which is free when the model repeats itself. On Qwen3.8's recurrent GDN layers it could not batch, and its prefill recorded no recurrent checkpoints, so a shared document was always a full miss.

  • Warm 8K TTFT 9.5–9.9 → 1.55–1.60 s; copy decode 157 tok/s against ordinary 32.
  • B4 25–26 → 55–63 tok/s on the closing run (ordinary 62–63): the cohort polls every verified token, keeps its batched views and pipelines plain rounds like ordinary decode. FINDINGS-GPU.md (final-pld)
Mechanism 5 · prefill geometry · research

Packed variable-length rows, chosen by an adaptive geometry planner

research routedefault-offobserved-used

A rectangular batch pads every request to the longest one, and padding rows pay full MLP and attention cost. Packing concatenates the real rows into one ragged tile with per-request offsets; a batch_geometry planner chooses rectangular, bucketed, packed or mixed by cost.

  • Adaptive multi-user geometry replay avoided 17.45% of padded rows (a geometry measure, not speed).
  • A 10-minute arbitrary-traffic A/B of the native N20 route was 7.44% slower overall; padding share alone did not predict wins.
  • Sweep: compaction declines are counted (6b5f6aed3), the planner fails closed beside SRPT (4a0c00bae), the varlen pair is one operator-owned default (29056b2fb).
Mechanism 6 · semantic state · research

A semantic activation capsule bus, and the false green it hid

researchunqualifiednot a public HTTP API

The capsule bus (95caa1405) steers the model's activations instead of adding prompt tokens. Its M3 mechanism gate passed, but the sweep found that serving applied it at a different seam than the gate measured.

  • Also fixed: a 0-error report on a waypoint 55% off (CAP-1), a one-shot capsule re-applied every step (CAP-3), a crash at step 0 (CAP-7), exact-prefix reuse for capsule requests (CAP-6), refusal at mount (ede895393).
  • Verdict CAP-9: nothing in the server calls the bus yet; quality and performance qualification are open.

Chapter 4 · The power governor

Publish the energy, then let the grid turn the dial

Telemetry says what a token costs; the governor holds a watt budget an operator or a grid signal can change at runtime.

If a server can say what each token costs in joules, and accept a ceiling at runtime, it can take part in grid demand response: shed load when the grid is stressed, run flat out when power is cheap and clean. mlx2 now does both halves. Power telemetry publishes the energy; the governor turns a requested watt budget into scheduling, without privilege and without touching clocks.

A correction we made
The first run paced B1 decode to about 11 tok/s under 25 W, which we read as wind-up from host-wide power on an idle engine. We added anti-windup (f030c22fa) and re-ran. The real reason: B1 decode alone draws about 38 W of GPU + DRAM, so a 25 W budget legitimately throttles it. Anti-windup stays, because on a shared host idle wind-up is real. FINDINGS-GPU.md
  • No clock control: macOS gives userspace none. The governor decides when the scheduler rests, how many lanes admission fills, and how long an idle server waits to form a cohort. Outputs change only through batch width, and receipts say so.
  • Never starved: duty never drops below its minimum and one rest never exceeds 1 s; a stale power signal holds the throttle instead of releasing blindly.
  • Power is whole-SoC: other work on the host counts against the budget. Default-off and unqualified.
  • Next: a burst-reserve mode that keeps background load under the sustained level so interactive prefill can spend the 90 s burst; it needs request priority classes.

P1 · CAP-2

The capsule that claimed to work

Serving applied the activation capsule on the last prefill row. At the shipped injection layer (31 of 32) nothing reads that row, so output was bit-identical to ordinary decode while the receipt said observed_used=true.

Found by tracing the serving seam against the M3 gate's seam and a tiny-model repro.

cd330ca82 — the capsule rides the prompt-tail forward; receipts advance only from that forward.
P0 · AQ-1

Qwen3.5-122B could not start

With the default --lane-matmul auto, the 122B loaded about 68 GB of weights and then died with an AttributeError: a lane hook added on 5 October read an attribute the 122B adapter never sets.

Found by an AST scan of the attributes each adapter class stores against the hooks serving calls.

f30cce87d, plus its own numerics contract and prefill default (5520c495a).
P1 · SS-2 / SS-3

A 9.5-second decode stall on Flash-Next

Beside a 16K prompt, a decoding lane on the served Flash-Next policy waited 6.9–9.5 s between tokens; ordinary waited 0.50–0.56 s. The stall bound kept a running maximum and self-MTP preparation was invisible to it.

Measured in the sweep's Flash-Next A/B; mechanism confirmed by CPU repros of the estimator.

d28a774aa + the co-arrival fixes: final max gap 440–475 ms, B8 median TTFT halved.
P1 · SPEC-10

Prompt lookup ran one lane at a time

On Qwen3.8's recurrent layers PLD could not batch, so four lanes ran four serial B1 rounds: 25–26 tok/s aggregate against 66–68 for ordinary, plus a replay forward on every partial acceptance.

Explained from the GPU route A/B down to the cache-topology check that refused hybrids.

2942ee30b, 82bdcc230 — batched, warm reuse fixed, B4 at parity with ordinary.
P1 · COW-1

The prefix cache paid twice

Every APCv2 entry published by a lane re-counted the recurrent snapshots it shares with its siblings: 3.25 MiB charged for 2.25 MiB held in the repro, up to about 5× on long hybrid prompts, so fewer entries fitted.

Found reading ArraysCache.nbytes against publication; failing CPU repro.

cc4e96bac — one physical-buffer ledger; evicting an entry frees exactly its charge.
P1 · CQ-4

Selected but never required

Several default-on mechanisms (Flash-Next fused GDN prefill and MoE weighted sum, lane matmul, base fairness) had counters but no engagement requirement, so a route could qualify without running them.

Found by diffing the default-on list against the qualifier's required checks.

Caught during integration

Five defects appeared only when the fixes met each other, main, or the GPU. Each was found by a failed start or a campaign number that did not make sense.

Integration · 9f9a81f86

Every guarded adapter refused to start

Parsing the new APC retention policy imported runtime.apc_v2, which loaded the model base before any adapter pinned its import-time environment. Qwen3.8-27B, Flash-Next and every other guarded adapter died with ImportOrderError. A fresh-interpreter test now builds the adapter first.

Integration · e33356767

A main commit broke the default DFlash2 route

66b2f9d1e attached proposal composition to every external drafter, including the pinned tree pair, which refuses composition. The final route campaign could not start DFlash2. Composition now defaults on chain routes only; the A/B below shows the tree route back to its numbers.

Integration · b02360126

The snapshot ledger synchronised the device

The COW-1 fix keyed its ledger by evaluating arrays, forcing a GPU sync on every APCv2 store during prefill. The post-fix campaigns ran with it, which is why only the final tree's numbers are quoted as after.

Integration · e4213207f; 057373692

Co-arrived Flash-Next prompts admitted in waves

The first co-arrival hold bounded the wait by the siblings' sum, so eight prompts started in waves (TTFT 1.3 s, then 8.9 s, then 12.2 s). Bounded per sibling and prepared together, median B8 TTFT halved instead.

Integration · f030c22fa

The governor wound up on an idle engine

Whole-SoC power includes other servers' work; an idle budget server integrated it into its throttle. Anti-windup now holds the throttle while the engine is idle (see the correction in the governor chapter).

Chapter 11 · Place in the field

Deep local state, in a shared field

Carried over from the September edition and still true, with this week's additions.

Apple-native servers and larger inference engines overlap on APIs, batching, prefix reuse and speculation. mlx2's focus is the composition: adapter-owned model state, a single exact prefix-cache authority, physical memory accounting and receipts that distinguish configuration, confidence and execution.

Apple-native serving · oMLX, Rapid-MLX. oMLX documents continuous batching, shared copy-on-write prefixes and memory/SSD cache tiers. Rapid-MLX combines an MLX server and Mac application with OpenAI/Anthropic APIs, coding-agent tools and release gates. Overlapping capabilities; a cache or endpoint alone is not a uniqueness claim.
Native speculative decoding · MTPLX. MTPLX specializes in native MTP on Apple silicon. mlx2 combines embedded-head MTP, prompt lookup and external drafting (now a token tree) with ordinary references, adaptive depth, memory admission and cache transactions.
Desktop and client workflows · Ollama, LM Studio. Ollama provides a documented subset of OpenAI-compatible APIs; LM Studio documents Responses, Chat Completions, Embeddings, tools, structured output and Anthropic Messages. mlx2's shared lifecycle serves familiar clients and refuses unsupported features explicitly.
Broader engines · vLLM, llama.cpp. vLLM documents automatic prefix caching including hybrid-state considerations; llama.cpp documents parallel decoding, continuous batching and server APIs. mlx2 concentrates its state and evidence contracts on Apple silicon instead of claiming wider coverage.

Capability comparisons from primary documentation checked on 27 September 2026, not benchmark rankings. This week's peer PR survey (oMLX, Rapid-MLX, llama.cpp, vLLM, SGLang, MTPLX, mlx-vlm and others since 22 Sep) found most peer mechanisms already present and fed four applicable peer bugs into the sweep (B1–B4).

The moat is the composition

A single state constitutionAPCv2, request revisions, fidelity and plane identities cover warm reuse, speculation, rollback, spill, surgery, compaction and bounded approximation.
Hybrid architecture depthPLE, QSA, GDN, MoE, MTP and now draft trees are optimized as interacting parts of one model, with their memory geometry and rollback semantics.
Receipts all the way downThe API result connects to scheduler decisions, cache reuse, actual width, speculative acceptance, kernel counters, and now energy and the power governor's actions.
Failure as a product featurePartial fanout, unsupported fidelity, stale revisions, unobserved mechanisms and memory shortfalls are designed outcomes.
Provenance without dependency dragProven ideas are mined mechanism by mechanism and attributed; the TensorFold executor is vendored and owned rather than imported.
Institutional memoryNegative experiments (this week: N20 at arbitrary traffic, GDN chunk-16, LLaDA, a histogram MoE planner) keep folklore from becoming defaults.
Read the evidence at its actual scope
  • Confidence: a route may run unqualified with an explicit label; only matching source, runtime, artifact and settings evidence supports “qualified”. The new Qwen3.8 default is a candidate.
  • Execution: HTTP concurrency, configured lanes and physical model width are different measurements; receipts report observed work.
  • Fidelity: exact reuse, numerically bounded kernels and approximate operations carry different contracts; near ties are classified, not ignored.
  • Performance: sweep A/Bs are two-repetition evidence on one laptop; quoted performance needs a controlled run, and heat moves results.
  • Maturity: mlx2 is experimental research software; interfaces, formats and policies are still moving.
