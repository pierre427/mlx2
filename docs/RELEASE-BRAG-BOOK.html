The category distinction

Beyond a framework. Beyond a generic server.

MLX supplies native Apple-Silicon arrays, lazy execution, unified memory, streams, compilation and model-building primitives. mlx2 adds the layer MLX deliberately does not try to be: an inference control plane with transactional model state, route qualification, memory admission, specialized decoding paths and end-to-end receipts.

Apple SiliconUnified CPU/GPU memory, Metal execution and device working-set constraints.
MLXArrays, operators, lazy graphs, compilation, streams and extensible kernels.
Model mathQwen hybrid attention/recurrent layers, MoE, PLE, GDN, QSA and draft heads.
mlx2 runtimeAPCv2, continuous batching, transactions, admission, speculative execution, route policy and observed-use telemetry.
mlx2 productOpenAI- and Anthropic-compatible APIs, agent clients, bounded resources, cancellation, qualification identities and operational telemetry.

The central idea: mlx2 does not merely expose kernels. It composes kernels, cache state, scheduler policy and API semantics into a single revision-bound transaction—and refuses to claim a feature when its mechanism did not engage.

One connected system

Each feature makes the others safer and more useful.

The architecture is deliberately compositional. Model descriptors keep tensor math out of the scheduler. APCv2 gives every optimization one ownership language. Admission reserves the real footprint before execution. Qualification measures the whole arrangement against pinned evidence. Receipts close the loop at request time.

Source-bound qualification

Measured routes, precise limits.

The September campaign exercises ordinary decode, APCv2 and physical batching on separate M5 Max and M3 Pro hosts. A passing workload is evidence for that artifact, source, host and policy; it is not a blanket qualification of every optimization.

M5 / QWEN3.8 MLX 4-BIT

400 of 400 domain checks

Four-lane 20×20 batching passed with APCv2 repeated-prefix reuse, zero HTTP errors and zero owned-run swapouts. Median aggregate generation was 46.8 tokens/s across the mixed workload; this is not single-stream speed.

M3 / QWEN3.8 MLX 4-BIT

Cross-host stress pass

A current-source four-lane 20×20 run passed 400 of 400 with APCv2 reuse and zero swapouts. Median aggregate generation was 13.8 tokens/s. Its basic context ladder is a separate gate.

M5 / QWEN3.8 MTP OQ4E

32K warm reuse depends on capacity

An 8 GiB APCv2 cap missed one of four warm lanes in each of three width-four repetitions. A 16 GiB capped rerun passed all four lanes, all three repetitions and all 30 needles with zero swapouts. The long-context admission gate remains separate.

Where to inspect: Qwen3.8 MLX 4-bit results, Qwen3.8 MTP results, and the campaign index. Historical model pages retain their own source revisions; the product source review below is a later snapshot.

What is hardest to copy

The moat is the composition.

Individual kernels can be reimplemented. The harder asset is the set of boundaries that lets many advanced mechanisms coexist without lying about correctness, memory, or execution.

M01

A single state constitution

APCv2, request revisions, fidelity and plane identities cover warm reuse, speculation, rollback, spill, surgery, compaction and explicitly bounded approximation.

M02

Hybrid architecture depth

PLE, QSA, GDN, MoE and MTP are optimized as interacting parts of one model, including their memory geometry and rollback semantics.

M03

Receipts all the way down

The API result can be connected to scheduler decisions, cache reuse, actual width, speculative acceptance and kernel counters.

M04

Failure as a product feature

Partial fanout, unsupported fidelity, stale revisions, unobserved mechanisms and memory shortfalls are designed outcomes—not undefined behavior.

M05

Provenance without dependency drag

Proven ideas are mined mechanism by mechanism, attributed and adapted, while the serving core stays independent of the unified checkout and optional runtime dependencies remain explicit.

M06

Institutional memory in code and evidence

Negative experiments, automatic-selection gates and mechanism-specific tests prevent benchmark folklore from becoming defaults.

Read the evidence at its actual scope

  • Confidence: a route may run unqualified with an explicit warning. Only matching source, runtime, artifact and settings evidence supports the qualified label.
  • Execution: HTTP concurrency, configured lanes and physical model width are different measurements. Receipts report observed work.
  • Fidelity: exact state reuse, numerically bounded kernels and approximate operations carry different contracts. Quantized KV, int8 prefill, semantic bridges and relaxed verification are explicitly bounded.
  • Performance: faster components and isolated runs do not establish a faster complete workload. Ordinary decode remains the reference.
  • Models: candidate media traces, partial ladders and an offline diarization qualification do not qualify every HTTP route or host.
  • Maturity: mlx2 is experimental research software; its interfaces, formats and policies remain under development.
