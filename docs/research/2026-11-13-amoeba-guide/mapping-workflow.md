# Amoeba mapping workflow

*2026-11-16, approved by Pierre as the foundation document (this file at the newest main commit that touches it is the spec). A reusable procedure for carving any model into an English core plus gated boxes. First written up from the Qwen3.8-27B and Qwen3.8-Flash-Next runs.*

## 1. What it produces

For one model checkpoint the workflow produces:

- **A core:** always on. English, plus the units that most categories share.
- **Boxes:** one per category, per language and per untagged cluster. Each box opens only when its content shows up in the token stream.
- **Cross-box tiles:** units shared by exactly two boxes. A cross-box tile loads whenever either of its two boxes loads.
- **A partition:** every unit lives in exactly one place (the core, one box, or one cross-box tile). With everything open, the parts reproduce the original model exactly.
- **A gate per box:** detected automatically from the model's own hidden state, never set by hand.
- **A registry entry per box:** taxonomy ID, size, held-out quality, gate rates, and source checkpoint and commit.

More boxes is better than fewer. At serving time we want to load only the boxes a request needs.

## 2. Inputs

| Input | What it is | Where |
|---|---|---|
| Checkpoint | The model, named `<artifact>@<fingerprint>` | `~/mlx-models/...` |
| Taxonomy | Usenet-style dotted topic IDs (`prog.c`, `sci.medicine`, `lang.fra`). IDs are permanent and shared across models. | `docs/research/amoeba-topics/taxonomy.v1.json` |
| Probe corpus | Short texts per taxonomy node, split into **fit** and **held** by a hash of the source group, so one source never lands in both. | `research-artifacts/amoeba/topic-probes-<hash>/` |
| Validation texts | Whole documents kept apart from fit and held, used to choose box sizes. | built from the probe corpus or the topic corpora |

The same taxonomy and probe corpus serve every model, so results compare across models by topic ID.

## 3. Units

- **Dense models:** one unit is one MLP neuron.
- **MoE models:** one unit is one neuron inside one routed expert (`--moe-units neuron`). Whole experts (`--moe-units expert`) are a coarser first pass. Shared experts and attention always stay in the core.
- On Flash-Next, neuron units gave a smaller box that was 54% more topic-specific than whole-expert units.

## 4. Data rules

These are fixed defaults. Change them only when a box misses its target, and only as a better-data fix.

1. **Windows come from random positions across the whole document,** several per long document, seeded and recorded. Never take only the first tokens of a document. Document openings are often titles, headers or boilerplate.
2. **Strip shared templates.** Drop any opening shared by at least 2 rows and more than 20% of a topic's rows (system prompts, legal headers).
3. **Code documents start at their first line of code.** Many code datasets open with an English task statement.
4. **Window length 128 tokens** by default.
5. **On-policy continuations.** For each prompt (a 96–128-token passage from mid-document), the full model writes one greedy and three temperature-0.7 continuations of 64 tokens, with recorded seeds. The carve scores the continuation plus the last 32 prompt tokens.
6. **Held text is never generated by a model,** and is never used to choose anything. It is only checked.
7. **Do not carve hand-picked task boxes.** Boxes come only from the taxonomy and from autodetected clusters.

## 5. Steps

### Step 1. Map and tag
1. Capture each unit's activation peak on every probe window, fit and held. Fit windows drive the clustering. Held windows are kept for the tagger's checks.
2. Cluster the non-core units by how they fire together (spherical k-means; k ≈ 50–130, depending on model size).
3. Tag each cluster with the taxonomy IDs that are enriched in its top sequences, against twin and shuffled-label controls. Use a removal check where there's time: switching the cluster off should hurt its topic more than a random twin does.
4. Untagged clusters keep a cluster ID. They still get a box.

### Step 2. Core
1. Carve the core on English prose only: a joint mask over all layers (see §6), judged by KL to the full model. Graded cores (T1 grade school, T2 high school with T1 fixed) are optional.
2. **Check that it's English-only:** score held non-English probes with the core alone; they should be poor. Score held English too; it should stay near the full model.

### Step 3. Boxes
1. **Make one box per tagged category, one per language and one per untagged cluster.** Languages share a box only if they cluster together in Step 1. There's no hand-made family list.
2. **Order:** branch level first (`sci.biology`, `prog.python`, language families), then split into leaves wherever a branch box is large or its leaves separate in the map.
3. **Carve each box with the core fixed:** a joint mask over the units outside the core, on the box's fit text plus its continuations, judged by KL to the full model.
4. **Size:** choose the box's size on validation documents, aiming at **+0.05 nats minus the measured validation-to-held gap** (use +0.03 until the gap is measured).
5. **Check:** score the box once on held text: corpus windows, greedy continuations and temperature-0.7 continuations.
   - **Pass:** core + box is within **+0.05 nats** of the full model on held text.
   - **Miss:** Pierre, 2026-11-16: "The 0.05 nats is important, if you don't hit it you need better data and carve more neurons". So a miss is fixed with **better data** (extend that topic's probes with more variety and depth) and **more neurons** (re-cut larger, choosing the new size on validation text at a tighter margin). Then re-check on held. Never widen the target. Never choose the size by looking at held: held only confirms. Report every miss with its numbers.
6. **Control:** every box must beat a random box of the same size, by a clear margin.

### Step 4. Partition
Pierre, 2026-11-16, on the overlap rule: "a unit shared by 3 or more experts goes to the core (confirmed). 2 experts → cross-box shared tile".

For every unit outside the core, count the boxes that claim it:

| Claimed by | Goes to |
|---|---|
| the core, or 3+ boxes | the core |
| exactly 2 boxes | a cross-box tile for that pair |
| exactly 1 box | that box |
| no box | a remainder tile, grouped by cluster |

Nothing is pruned. **Check:** with everything open, the partitioned model reproduces the full model exactly.

### Step 5. Gating
1. For each box, train a detector on the model's own early-layer hidden state, from fit probes (the box's topic against everything else).
2. **Offline check, per box:**
   - **false-open rate** on unrelated held content: it should be close to 0. For example, the Chinese box should never open on English;
   - **miss rate** on matching held content.
3. **Runtime:** the server detects each box's content in the token stream and opens only those boxes. A box with no matching content never loads. This is automatic, with no manual flags.

### Step 6. Report and register
For each box, record:
- taxonomy ID;
- unit count and share of the pool;
- held cost on text, greedy and temperature-0.7;
- the random-box margin;
- gate rates;
- cross-box tiles it shares;
- checkpoint and commit.

Add every box to the shared registry under its taxonomy ID.

## 6. How a carve works

- **The carve is joint across all layers.** It learns one straight-through mask over every layer's units at once, and minimises KL to the full model plus a sparsity penalty. An answer depends on a cone of activations that widens backward through layers and positions. So units must be chosen together, never one by one or by routing frequency. Routing statistics may only seed the mask.
- **Gradients go one layer at a time** (`--grad-mode layer_ref`). Only one layer's working state is held in memory.
- **Bisect:** after the mask is learned, binary-search the keep fraction to hit the target, and score the true masked loss at each step. The exact masked evaluation always has the final say.

## 7. Checks that guard the code (once per model and commit)

These protect against bugs, not data problems. Run them in a short smoke test before the real carve:

- **Parity:** with every unit open, the patched model matches the stock model exactly (top-1 100%, KL 0).
- **Per-layer check:** for each layer, compare the fused path with the reference path. The change between them should be at most about 2%.
- **Gradient direction check:**
  - compare the gradient against finite differences;
  - for MoE, replay the expert choices from the unperturbed run;
  - use bf16-safe step sizes (2^-4 to 2^-1).

  For each box after that, the check is a diagnostic. It refuses only on real faults: correlation below 0.9, a size ratio outside 0.67–1.5, or no clean test directions.

## 8. Running it

- **One model per process.** Keep under the per-process memory cap (80 GB; Flash-Next carve jobs 92 GB by Pierre's approval). Watch footprint, not RSS, and stop on swap growth.
- **Load the model the way it's served,** with its production performance profile. Use fused kernels for forward-only work, and reference ops only inside the layer being differentiated.
- **Big models:**
  - **Flash-Next:** PLE offload, asserted at load.
  - **A model that doesn't fit in memory (DS4.1):** stream layers from fast storage. It needs a streamed backward pass, which is not built yet.
- **Models that don't fit in memory: rolling layer-window capture** (Pierre, 2026-11-16, "make sure it gets used whenever we want to do the mapping for large models"). `mlx2 amoeba` switches to it automatically when the resource plan says the model won't fit under the cap (`--stream rolling`, window `K` chosen from free memory):
  1. Keep the whole corpus's hidden state in memory: one row per token, all residual streams for hyper-connection models.
  2. Run one layer over **all** prompts, updating the state in place, while the next K layers load in the background. Drop the finished layer and load the next one. Every weight is read once, and disk reads overlap compute.
  3. No KV cache or APCv2 is needed: each layer builds its own keys and values from its input within the pass. Per-layer inputs such as PLE are recomputed from token IDs.
  4. If the state plus K layers doesn't fit, split the corpus into the fewest chunks that fit. Each extra chunk is one more read of the weights.
  5. Generation can't run this way, so continuations are produced first by normal serving, then captured as fixed text.
  6. The carve's backward pass uses the same scheme in reverse, saving every fourth boundary and recomputing the rest.
  7. Before trusting it on a new model family, check parity: rolling capture must match the normal forward pass on a model that fits.
- **GPU windows:**
  - pause the production service;
  - take the GPU lock;
  - use a fresh output folder for each attempt;
  - keep one gate file alive for the whole run, so other jobs wait.
- **Before any GPU run:** commit the code, then get a fresh-context review, then run.
- **Every receipt names** `<artifact>@<fingerprint>` and the mlx2 commit.

## 9. Lessons from the first runs

- **Data quality decided most outcomes.** First-64-token windows carved English task statements, shared templates and headers instead of the topic.
- **A box chosen on its own documents' spare text looked fine but missed on new documents,** about twice too small. Choose sizes on separate validation documents.
- **Per-box gradient checks in bf16 are mostly noise.** Treat them as code checks, run once per model and commit.
- **Prose that the core already covers still gets its box.** If the core alone is close (within about 0.05–0.06 nats), the box will be small. Keep it anyway, because more boxes is better.
- **Expect large overlap between related boxes** (C++ and Python: 0.20 Jaccard). Cross-box tiles and the 3+-boxes-to-core rule absorb it.

## 10. Pierre's decisions on structure, quality and speed (2026-11-16)

Quoted or closely followed from the alignment audit (`docs/research/2026-11-16-amoeba-alignment-audit.md` §8):

- **Tile structure follows the neurons.**
  - Languages that share many neurons (Latin and the Romance languages) can be one tile.
  - Pairs that share little are separate experts.
  - Pairs that share a lot, but only with each other, get a shared tile between them.
  - Programming is one master coding tile with many sub-tiles per language or topic, called on need.
  - A huge tile is a candidate to split. **Never one master plus one sub-tile.** One master with many sub-tiles is the intended shape.
- **A box holds only neurons exclusive to its topic,** and removing it must not damage other topics. This applies to every box and to the full carve-out (Pierre, 2026-11-16, via the 27B session). Every box is checked by removing it from the full model and measuring held cost on its own topic and on unrelated topics and languages, against a random removal of the same size.
- **"Best" for a category** is measured on a larger held-out corpus, as an A/B: the original core plus the original box, against the same core plus the new box.
- **Core selection:** the best cores score well on English, creativity and prose quality.
- **Baseline and floor:**
  - Each model first gets an optimized mlx2 adapter, independent of tiling. That is the baseline.
  - Tiled serving (fused ops, fast gates) must always beat the base model's speed.
  - Quality on scored tests should preferably be better, and never lower than the base. Lower means the carve is wrong.
- **Licences:** every map, tile set, bundle and prompt set carries each source's licence in its metadata.
- **Memory:** per-job caps hold until the super-model stage. Then the whole M5 is available, with :8282 paused.
- **One spec, one queue owner, verbatim quotes:** this document is the spec. Briefs link to it and quote Pierre verbatim with a date.
- **Small models** (below 8B) are used only as fast smoke tests, and are labelled as such in their receipts.

## 11. Versioning: taxonomy, maps and tile sets

These rules come from Pierre, 2026-11-16.

- **This taxonomy is the foundation.** Later versions never have fewer categories than this one. They only add categories. IDs stay permanent: a retired node is marked deprecated and points to its replacement, and it is never deleted or reused.
- **Maps work across taxonomy versions.** A map defines each category and the neurons that carry it. So a map made with an older taxonomy version still works with a newer one, and a map made with a newer version still works with an older one. Categories one side doesn't know are simply absent on that side.
- **A tile set always ships with its map, its taxonomy and its prompt set.** A carved, baked tile set (core, boxes, cross-box tiles) is tied to the exact map and taxonomy version that produced it, and to every prompt used to make it. It must be distributed with all three, recorded by version and hash, together with the model checkpoint fingerprint.
- **The prompt set** is one Parquet file, plus a small JSON manifest that holds its schema, hash and counts. It holds every text used in mapping and carving:
  - probe windows for fit, validation and held, and the core's tier prose;
  - each window's document ID and token offset;
  - the generation prompts and the model's continuations (mode, temperature, seed);
  - the taxonomy topic and the split.

  Each row also carries its **origin** (natural, lab, template or synthetic), **source**, **source revision** and **licence**, so the set can be redistributed under each source's terms. Parquet is used because it is compact and typed; the manifest lets a reader check the file without opening it.

## 12. Targeted extraction and transfer to another model

**Goal (Pierre, 2026-11-16):** point at a new model that is good at category X, extract just that category's neural map as an expert box, and use the box in another model.

```
mlx2 amoeba extract --model <donor> --topic <taxonomy id> --out <dir>
mlx2 amoeba install --box <dir> --host <model>      # fits the donor→host maps
```

### 12.1 Extract (on the donor alone)
1. **Check the donor really is better at X (the donor-gap screen).** Score the topic's held probes on donor and host as per-byte NLL, bare and with a neutral prefix, centred on each model's whole-corpus offset. Extract only if the donor leads in both conditions with 95% confidence.
2. **Core:** reuse the donor's cached English core, keyed by checkpoint fingerprint, or carve a quick one.
3. **Carve the box** with the core fixed, as in §5 step 3: the taxonomy probes plus continuations, +0.05 nats on held, and extend the probes on a miss.
   - **MoE donors:** neuron units inside experts.
   - **Optional attention heads** as carvable units (`--attention-units heads`).
   - Seed the mask with the donor's map clusters for the topic. Where the host shares the donor's tokenizer, the expert token signatures can seed it too (§12.4).
4. **The box bundle holds:**
   - box weights and mask, and the cross-box tiles it touches;
   - its gate detector;
   - the donor's map, taxonomy version and prompt set;
   - the donor fingerprint and its measured quality on the donor;
   - the donor-gap screen result.

### 12.2 Find the host's side (the topography)
The taxonomy topic ID is the join key between the two models.
1. **Host stub:** the host's own map gives its neurons for the same topic ID. If the host is weak at X, its stub is small, and it's what gets replaced or supplemented.
2. **Layer warp:** a monotone warp, fitted on layer similarity (CKA), pairs donor layers with host layers by relative depth. Middle layers align best (CKA 0.6–0.7).
3. **Ridge maps per layer band:** fitted on **paired text both models read**. Tokens are paired where both tokenizers end at the same character. Fit them on **broad probe data, never on the skill alone.** A map fitted on narrow data memorises: 98% on its fitted facts, 0% on new ones (0.6B → 4B). Rotation only (Procrustes) is not enough. Ridge maps held KL 0.03–0.11 and 96–99% top-1 on Qwen and Gemma donors. Flash-Next is worse with depth (KL 0.09 → 0.59).
4. **Shape-only alignment doesn't work.** Gromov-Wasserstein and relative representations are too weak. Topology (persistent homology) is useful only as a check that a mapped region keeps its structure.

The warp, maps and stub are per donor–host pair, and are stored in the install output next to the box.

### 12.3 Use the box in the host: the routes, best first
| Route | What runs | Status (2026-11-16) |
|---|---|---|
| **Side stream** | The donor's core plus the box run beside the host. Their predictions blend at the output through the box's gate. | **Works.** Gemma-26B into Qwen3.5-4B: decimal problems 5/12 → 8/12 with the box alone, 10/12 with the whole donor. Costs: the donor core stays loaded, and English drift on unrelated text is 0.24–0.35 KL, so the gate must stay closed off-topic. |
| **Mapped injection** | The box's output, translated by the warp and ridge maps, is written into the host's hidden state over a layer span, gated, and capped at 0.25× the host's own per-layer change (the blend-in rule). | **Not working yet.** At full strength it derails the host. Gently, it does no better than a random box. |
| **Distilled tile** | Train a new gated tile in the host to copy the donor's behaviour on the topic. | **Not working yet.** CWE, Flash-Next → 27B: no gain over the start at either blend-in budget. Plain training on the topic text helped (0.472 → 0.426), but that isn't transfer. |

`install` defaults to the side stream and keeps the other two as experimental options. Each route reports, against its controls (host alone, shuffled map, random box of the same size):
- the host's held quality on X;
- English drift on unrelated text;
- gate false-open and miss rates;
- cost (memory, tokens/s).

### 12.4 Matching experts directly (MoE donors with a shared tokenizer)
Static, weights-only, on the CPU. Read each expert through the vocabulary: per-token energy signatures, and neuron-to-neuron correlation. Match experts across models whose tokenizers are byte-identical (check the tokenizer hash). Report a match only above both a row-permuted expert ceiling and a random-expert baseline. Most apparent matches don't survive those controls (Kimi K3 ↔ Kimi Linear: 4 tight matches over 2,473 experts).

## 13. Per-model checklist

- [ ] Checkpoint fingerprint recorded; dense or MoE; unit type chosen
- [ ] Memory fits under the cap (or streaming planned)
- [ ] Smoke test passed: parity, per-layer check, gradient check, step time, peak memory
- [ ] Step 1: map captured, clusters tagged
- [ ] Step 2: core carved, English-only check passed
- [ ] Step 3: boxes carved; held +0.05 pass/miss list; misses' probes extended
- [ ] Step 4: partition exact
- [ ] Step 5: gate rates per box
- [ ] Step 6: registry updated, evidence committed
